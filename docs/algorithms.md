# Algorithms and their bounds

The paths that touch every row of a table, or every key, and what keeps each
one from holding a table in memory. A bound here is one a test or a benchmark
checks: the last column names it, as `path::test` or as the command to run.
Numbers are from one laptop ([performance](performance.md) describes it);
they size nothing but the shape of the curve.

`n` is the number of rows (or keys) of the side read, `p` the number of
partitions, `s` the rows the diff and the deletes hold in memory before they
spill (`SPILL_ROWS`, 50,000).

| Path | Algorithm | Time | Memory | Proof |
| --- | --- | --- | --- | --- |
| Cutover diff, first pass (`core/cutover/diff.py`) | One read of each side; a 64-bit digest per row (`checksum.digest`), summed per partition. Partitions are ranges of about `ROWS_PER_PARTITION` (100) target rows when the target orders its key as the canonical forms sort, hash buckets of the key text otherwise (SQL Server orders a `uniqueidentifier` by its last bytes). | O(source + target) rows, each digested once | 32 bytes a partition (`_Sums`: two arrays of 64-bit counts and sums), one key a range, at most `MAX_PARTITIONS` (500,000): 16 MB | `tests/units/core/test_cutover.py::TestTheSecondPass::test_keys_the_target_orders_otherwise_split_by_hash`; `tests/integrations/databases/test_reconciliation.py::test_uuid_keys_reconcile_whatever_the_order_of_the_database` |
| Cutover diff, second pass | Only the partitions whose count or sum differ: the source read again whole and its rows of those partitions sorted by (partition, key) through the external sort below; the target read again by range (`lower`, `upper` on the key, in the database's order) or, with hash buckets, whole and sorted too. One sorted merge compares key by key (`_merge`). | O(source) again, plus the target's differing ranges (ranges) or O(target) again (hash); sorting O(d log d) for the `d` rows of the differing partitions | `s` rows plus one row per run on disk; the partitions of the first pass | `tests/units/core/test_cutover.py::TestTheSecondPass::test_reads_again_only_the_ranges_that_differ`, `::test_rows_past_the_memory_are_sorted_on_disk` (spills every 7 rows); `tests/integrations/databases/test_reconciliation.py::test_the_second_pass_reads_only_the_ranges_that_differ`; `tests/e2e/test_cutover_signals.py` (the spill goes with a SIGTERM); `uv run python benchmarks/bench_diff.py --rows 200000`: 7.0 s and a peak of 94 MB with no drift, 15.3 s and 121 MB with 1% of the rows drifted (every partition differs); 5,000,000 rows peak at 127 MB ([performance](performance.md)) |
| External sort (`shared/utils/external_sort.py`) | Items are held up to `spill_rows`, then sorted (`list.sort`, stable) and written as a run, pickled in chunks; `heapq.merge` reads the runs back sorted, stable on equal keys (the earlier run first). Runs are tiered: `fan_in` (64) runs of a tier are merged into one run of the next, so a run is rewritten once per tier, not at every fan-in reached; the final merge takes at most `fan_in` runs, the newest merged first until they fit. The runs are in a directory of the owner only (`mkdtemp`), each removed as it is read, all of them when the sorter closes, is garbage collected, or the interpreter exits. | O(n log n) comparisons; every item written and read back once per tier: once up to 64 runs (3,200,000 items at `SPILL_ROWS`), twice up to 4,096 runs | `spill_rows` items, plus a chunk of `spill_rows / fan_in` items and a file buffer per run read, at most `fan_in` runs: `spill_rows` items in all | `tests/units/shared/test_external_sort.py::TestExternalSorter::test_items_past_the_memory_are_sorted_through_runs_on_disk`, `::test_runs_past_the_fan_in_are_merged_by_tiers`, `::test_a_merge_of_tiers_keeps_equal_keys_in_order`, `::test_a_run_holds_chunks_of_the_memory_shared_by_the_fan_in`, `::test_equal_keys_keep_the_order_they_came_in`, `::test_an_exception_mid_iteration_removes_the_runs`, `::test_a_sorter_garbage_collected_removes_its_runs`; `tests/units/shared/test_external_sort.py::test_equals_sorted_whatever_the_spill` (property, spills of 1 to 6) |
| Keyset reads (`infra/database/relational/tables.py` `RelationalTableReader.read`, `Dialect.after`) | Pages of `page_size` rows in `order_by` order, each after the last row of the previous one: `c1 >= v1 AND (c1 > v1 OR (c2 >= v2 AND ...))`, which an index on the order columns serves; never `OFFSET`, which scans what it skips. | O(n / page_size) round trips, each an index seek | One page | `tests/integrations/databases/test_tables.py::TestReader::test_pages_never_skip_nor_repeat_rows_on_ties`, `::test_after_lower_upper_and_filters` |
| Quantile partitions (`core/operators/partitions.py` `split`, `KeyPartitions`; `ITableReader.keys_at`) | The bounds of `p` ranges are the keys at the quantiles: one query per bound, `ORDER BY key OFFSET n FETCH FIRST 1 ROW`, each after the previous bound (keyset), so the database walks the key index once up to the last offset and only `p - 1` keys cross the network (relational and MongoDB readers). The default `keys_at` of the port reads every row up to the last offset. Bounds are computed once (`prepare`) and kept in the state. | O(n) index entries in the database, `p - 1` queries; O(n) rows read with the default | O(p) | `tests/integrations/databases/test_key_ranges.py::TestKeysAt::test_the_database_skips_to_the_rows_read_in_order`, `::test_split_finds_the_bounds_streaming_found`; `tests/units/core/test_partitions_by_key.py::TestKeysAt::test_split_asks_the_reader_for_the_keys_at_the_quantiles`, `::test_the_default_reads_up_to_the_last_offset` |
| Deletes found by reconciliation (`core/operators/reconciliation.py` `MissingSourceRows`) | The source's key columns are read by key, put in canonical form (`keys.canonical`) and sorted through the external sort; the registry's entries (`entries`, in the registry's order) are sorted the same way, each with its position; one sorted merge (`_absent`) yields the loaded keys the source lacks, which are sorted back by position: the same deletes as a set of every source key would find, in the same order. The guard (`max_share`, `confirm_deletes`) counts them before the first is yielded. | O(source + registry) reads, O(n log n) sorting on disk | `s` keys or so, whatever the size of the table (one million keys: a `tracemalloc` peak of 16 MB, against 223 MB with the set; ten million: a peak RSS of 66 MB, against 1,495 MB) | `tests/units/core/test_reconciliation_deletes.py::TestBoundedMemory::test_a_million_keys_are_compared_in_bounded_memory` (`tracemalloc` peak); `tests/units/core/test_reconciliation_deletes.py::test_one_column_keys_whatever_their_case_and_spaces`, `::test_composite_keys` (properties against the set); `tests/integrations/databases/test_change_capture.py::test_deletes_are_found_by_reconciliation` |
| Key registry (`infra/database/relational/bookkeeping/stores.py` `RelationalKeyRegistry`; `core/keys/tiered.py` `TieredKeyCache`) | `register` is one `INSERT` of the keys missing per batch, with no read first (`Dialect.insert_missing`); `known` one `SELECT ... IN` per `in_chunk` keys (the dialect's, 1,000 at most: [tuning](tuning.md)); `entries` pages of 10,000 by surrogate key (keyset). The cache in front is tiered: an LRU (`OrderedDict`) in memory bounded by bytes (the cost of an entry is sampled with `sys.getsizeof`), then a SQLite table (`journal_mode=OFF`) under `$TMPDIR` for what memory evicts, bounded by bytes too, then the registry; written through; `known` reads memory, then disk once for all the misses of a batch (`IN` lists of 900), then the registry once for the rest, and caches positive answers only. | One statement per batch of `register`, ⌈k / in_chunk⌉ per `known` of `k` keys; a memory hit O(1), a disk hit O(log n) per key | `key_cache_memory` bytes in memory, `key_cache_disk` on disk | `tests/units/core/test_tiered_cache.py::TestTieredKeyCache::test_hits_are_served_from_memory`, `::test_evicted_keys_are_served_from_disk_without_the_registry`, `::test_keys_in_the_cache_are_not_registered_again`, `tests/units/core/test_tiered_cache.py::test_the_tiers_answer_like_the_registry_alone` (property); `tests/integrations/databases/test_bookkeeping.py::TestKeyRegistry::test_an_idempotent_crosswalk_safe_under_concurrency`, `::test_behind_a_cache`; `tests/integrations/databases/test_concurrent_writes.py::TestKeyRegistryInserts::test_the_same_keys_registered_by_four_threads_at_once`; `make bench` (`benchmarks/bench_load.py`) times the registry per step |
| Quality gate (`core/quality/gate.py`; `core/mapping/quality.py` `ReferenceRule`; `core/contract/quality.py` `QualityReport`) | Before a batch is checked, each reference rule asks the registry about the distinct foreign keys of the batch, `chunk_size` (500) per call, not once per record. A report keeps `max_samples_per_rule` issues per rule by reservoir sampling (`shared/utils/sampling.py`, Algorithm R), merged across batches as drawing without replacement would (`merge_reservoirs`). | ⌈distinct keys / 500⌉ registry calls per batch and rule; O(1) per issue sampled | O(records of one batch); O(`max_samples_per_rule`) per rule | `tests/units/core/test_mapping_references.py::test_registry_calls_per_batch_are_bounded_by_chunks_not_rows` (2,400 rows, 1,200 keys: calls of 500, 500, 200); `tests/units/core/test_quality_gate.py::TestSampling::test_reservoir_samples_from_every_batch`; `tests/units/shared/test_utils.py::TestReservoirSampling::test_every_item_has_the_same_chance`, `::test_merge_of_two_streams_stays_uniform` |
| Redaction (`core/observability/redaction.py`) | A fixed set of compiled regular expressions over the text, every repetition bounded (`{0,512}`, `{0,2048}`) and the data patterns anchored to their line: an unbounded repetition made a long line quadratic. | O(length of the text) | O(length of the text) | `tests/units/infra/test_redaction.py::test_long_lines_take_linear_time` (lines of 200,000 characters and more, under 3 s each, best of three, where an unbounded pattern took minutes); `tests/units/infra/test_kafka_dead_letters.py::test_a_reason_of_a_megabyte_is_redacted_whole_then_cut` |
| Mapping engine (`core/mapping/compiled.py`; `core/mapping/casts.py` `text_parser`) | A field is compiled once into a closure (`_runner`: its source reader, transform and settler bound), the mapping into a tuple of them; a row costs one call per field, and the natural key of a key field is derived once for its value and its record. The columns of a row shape are checked once per shape (`_checked`). A date format written as in Excel is compiled once into a regular expression (`functools.cache` per format), where `strptime` compiles its own at every call. | O(fields) per row | O(fields); one parser per date format | `tests/units/core/test_mapping_date_parser.py::TestCompiledParserAgainstStrptime` (`test_any_text`: the compiled parser accepts and refuses what `strptime` does; `test_python_formats_and_odd_ones_keep_strptime`); `make bench` (`benchmarks/bench_load.py`): 7,076 rows/s Postgres to Postgres on one range, 1,000,000 rows, peak RSS 190 MB ([performance](performance.md)) |

When a change touches one of these paths, its proof runs with it: keep the
bound, or change this page with the code.
